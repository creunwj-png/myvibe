## 1. 개요
- **한 줄 정의:** 여러 프로젝트를 동시에 굴리는 PM이, 떠오르는 순간 폰에서 키워드만 툭 던지면 AI가 어울리는 프로젝트로 분류해주고, 고른 아이디어만 팀과 공유해 함께 발전시키는 — 가볍게 던지고 똑똑하게 정리되는 아이디어 캡처 도구.   ← idea
- **해결하는 문제:** 아이디어는 때·장소를 가리지 않고 떠오르는데, 가벼운 메모앱을 택하면 구조를 잃고(기록이 흩어지고 맥락이 증발), 구조화 도구(노션)를 택하면 그 순간이 무거워 놓친다. "어디에 기록하지?"라는 망설임 자체가 마찰이 되어 아이디어가 휘발된다.   ← idea
- **타깃 사용자:** 여러 프로젝트(서비스 고도화·신규 개발 과업)를 동시에 담당하는 프로덕트 매니저. 아이디어가 산발적으로 떠오르고, 빠르게 붙잡아 프로젝트에 연결하고 팀과 함께 발전시키려는 사람. 노션 같은 구조화 도구에 익숙하지만 빠른 캡처 단계에선 무겁다고 느낀다.   ← idea
- **플랫폼:** 반응형 웹 (모바일 우선 — 자기 전·이동 중 폰에서 즉시 꺼내 쓰는 게 핵심, 데스크톱 정리·검토까지 확장).   ← idea

## 2. 배경 & 근거
- **시장/경쟁 맥락:** "빠른 캡처"와 "구조화된 정리"는 시장에 따로 존재한다. Mem은 분류를 100% AI에 위임해 오배치·통제 불가 위험이 있고, Drafts·Google Keep·Idea(App Store)는 사용자가 100% 직접 분류해 "어디에 넣지?" 마찰이 남는다. Notion은 구조는 최고지만 모바일 즉시 캡처가 무겁다. 빠른 캡처 도구 대부분이 개인 도구라, PM이 여러 프로젝트를 미리 두고 그 위로 던지고 + 고른 것만 팀과 공유하는 조합도 비어 있다.   ← benchmark
- **우리의 차별 프레이밍:** *"던질 땐 메모앱처럼 가볍고, 쌓이면 노션처럼 프로젝트별로 정리되는"* — Keep과 Notion 사이를 잇는 **반자동 프로젝트 분류 + 선택적 팀 공유**의 모바일 우선 캡처 도구. 차별 두 축: ① **반자동 AI 매칭**(자동 오배치도 수동 마찰도 아닌, AI 추천→1초 선택의 중간지점 — 경쟁 4곳 모두 비워둔 칸), ② **PM의 다중 프로젝트 + 선택 공유**(개인 공간 기본 → 설익은 아이디어도 안심하고 던지고, "공유" 누른 것만 팀 보드로).   ← benchmark

## 3. 목표 (Goals)
- 떠오른 순간의 마찰을 0에 가깝게 — 폰에서 열어 키워드를 던지기까지 어떤 분류 입력도 요구하지 않는다.
- 던진 직후 AI가 분류를 좁혀줘, 사용자가 1초 선택으로 오배치 위험 없이 프로젝트에 정리한다.
- 쌓인 아이디어를 프로젝트별로 한눈에 점검하고, 고른 것만 팀과 공유해 함께 키운다.

## 4. User Scenarios   ← userflow

### Scenario 1 — 첫 던지기 (첫 사용)
- **사용자:** 톡캐치를 처음 여는 PM (프로젝트 0개, 게스트)
- **상황:** 이동 중·자기 전 갑자기 아이디어가 떠올라 휘발되기 전에 붙잡고 싶다.
- **목표:** 머릿속 키워드를 빠르게 저장하고 정리되는 경험을 한다.
- **흐름:** 환영 화면 → [바로 시작하기] → 캡처 화면(열자마자 커서)에 키워드 입력 → [던지기] → 담을 프로젝트가 없으므로 프로젝트 이름을 직접 입력해 생성·담기 → 홈에서 방금 메모가 프로젝트에 들어간 것 확인.
- **완료 조건:** 첫 메모가 사용자가 만든 프로젝트에 담겨 홈에 보인다.

### Scenario 2 — 반복 던지기 + AI 매칭 (반자동 분류)
- **사용자:** 프로젝트가 이미 몇 개 등록된 PM
- **상황:** A 프로젝트를 보다 B 아이디어가 연결되어 떠올랐다.
- **목표:** 망설임 없이 던지고, AI 추천으로 1초에 분류한다.
- **흐름:** 캡처 화면에 키워드 입력 → [던지기] → 같은 화면 아래로 AI가 기존 프로젝트 후보를 추천 → 후보 칩 1탭으로 분류 완료 → 홈에서 확인.
- **완료 조건:** 메모가 사용자가 1탭으로 고른 프로젝트에 분류되어 저장된다. (정 안 맞으면 새 프로젝트 또는 "분류 없이 저장"으로도 끝낼 수 있다.)

### Scenario 3 — 모아보고 공유 (회의 전 점검)
- **사용자:** 아이디어가 여러 프로젝트에 쌓인 PM
- **상황:** 회의 직전, 특정 프로젝트에 적어둔 걸 모아보고 팀과 나누고 싶다.
- **목표:** 한 프로젝트의 아이디어를 한눈에 점검하고, 쓸 만한 걸 골라 팀에 공유한다.
- **흐름:** 홈(프로젝트별 목록)에서 프로젝트 선택 → 프로젝트 상세에서 모인 메모 훑기 → 메모 상세에서 다듬기(수정/재분류) → [팀에 공유하기] → (게스트면 로그인) → 팀 보드에 올림.
- **완료 조건:** 선택한 메모가 해당 프로젝트의 팀 보드에 올라가 공유 완료 상태가 된다.

## 6. Success Criteria
- SC-001: 신규 사용자가 앱 진입 후 첫 메모를 30초 안에 저장한다. *(가설 — 사용성 테스트로 검증 필요)*
- SC-002: 프로젝트가 등록된 사용자가 메모를 던진 뒤 AI 추천 후보 선택으로 3초 안에 분류를 완료한다. *(가설)*
- SC-003: 사용자는 특정 프로젝트의 모든 메모를 한 화면에서 확인할 수 있다. *(관찰 가능)*
- SC-004: AI 추천 후보 목록에 사용자가 실제로 선택하는 프로젝트가 포함되는 비율(적중률)이 목표 기준 이상으로 유지된다. *(가설 — 목표 수치·측정 방법 미정, 오픈 이슈)*

## 7. Edge Cases
- **빈 상태(프로젝트 0개):** 첫 던지기에서 추천할 기존 프로젝트가 없으므로, 프로젝트 이름 직접 입력으로 생성을 유도한다. (Scenario 1)
- **빈 입력:** 내용이 한 글자도 없으면 [던지기]로 전진하지 않는다.
- **AI 추천이 부적합:** 후보가 맞지 않으면 사용자는 새 프로젝트 생성 또는 "분류 없이 저장"으로 흐름을 끝낼 수 있다.
- **미분류 누적:** "분류 없이 저장"한 메모가 쌓이면 나중에 정리할 수 있도록 별도로 모아 노출한다.
- **공유 시 로그인 이탈:** 게스트가 공유 단계에서 로그인을 취소하면 공유는 진행되지 않고 메모는 개인 공간에 그대로 남는다.
- **로그인 유도 거절:** 게스트가 시점별 로그인 권유를 닫으면 흐름이 끊기지 않고 게스트로 계속 사용하며, 작성한 메모는 로컬에 그대로 유지된다.
- **로그인/가입 실패:** 인증 오류(잘못된 정보·네트워크)가 나도 작성 중이던 메모·게스트 데이터를 잃지 않고 다시 시도할 수 있다.
- **메모 삭제:** 삭제는 실수 방지를 위해 확인 또는 되돌리기를 제공한다.
- **네트워크 불안정(캡처 순간):** 던지는 순간 네트워크가 없어도 입력은 보존되어야 한다(로컬 보관 후 동기화 — Assumptions 참조).
- **권한:** 팀 보드의 공유 메모는 연결된 팀원만 보고 코멘트할 수 있어야 한다.

## 9. 브랜드 & 디자인   ← brandvoice + DESIGN
- **서비스 이름:** 톡캐치 (TokCatch) — **확정**. (영문 표기 `TokCatch`는 App Store에 동일 철자 앱이 있어 글로벌·도메인 확장 시 다듬을 여지 있음 — 한국 타깃 우선이라 당장은 그대로.)
- **한 줄 무드:** 화자로 나서지 않는 도구 — 주인공은 PM 본인이고, 톡캐치는 배경에서 조용히, 간결하되 따뜻하게 아이디어를 제자리에 놓아준다.
- **보이스 요약:** PM의 작업 맥락을 이미 꿰고 있는 조용한 도구 — 던지면 군말 없이 제자리에 놓아주고, 필요한 순간에만 담담히 다시 꺼내 보여준다. 성격 3축: **간결한 · 빠른 · 믿음직한**. ("제가 분류했어요" 식 AI 생색도, 친근한 팀원 수다도 아님 — 주인공은 사용자.)
- **UI 카피 톤 가이드:**
  - *Do* — 던진 직후 어디 들어갔는지 짧고 따뜻하게 확인("B프로젝트에 담았어요"). 매칭은 후보를 나란히 펼치고 선택은 사용자에게("어디로 갈까요?"). 리마인더는 적어둔 키워드를 그대로 되살림.
  - *Don't* — 톡캐치를 화자로 내세우지 않음("AI가 분석했어요" ✕). 재촉·불안 자극 안 함("얼른/까먹기 전에" ✕). 감탄사·호들갑·자극성 이모지(🎉🔥) ✕. "저장 완료" 같은 시스템 로그 톤 ✕. 동기부여 코치 톤("연속기록/갓생") ✕. 푸시 알림 최소화.
  - 존댓말 기본(`~해요`), 이모지는 분류·완료 확인 자리에 최대 1개(`✓`), 느낌표 거의 안 씀. → 상세 docs/brandvoice.md 참조.
- **시각 디자인 시스템:** ✅ 확정 — docs/DESIGN.md (design-brandfit 산출물). 카카오 기반 디자인 시스템 — 평평한 화이트 캔버스 + 단일 시그널 옐로 `#FEE500`(던지기·매칭·완료 순간에만), Noto Sans KR, 12px 라운드 표준, 그림자 최소·배경색 레이어링으로 위계. 상세 토큰·컴포넌트는 docs/DESIGN.md 참조.

## 10. 범위 / 비범위 & 우선순위
- **v1 범위:** 즉시 캡처(FR-001), 게스트 시작(FR-002), 프로젝트 생성(FR-003), AI 매칭 추천→선택(FR-004), 미분류 저장(FR-005), 프로젝트별 모아보기(FR-006), 메모 수정·삭제·재분류(FR-007~009), 선택 공유(FR-010), 공유 시 로그인(FR-011), 검색(FR-012), 계정 로그인·게스트 데이터 연결(FR-016), 시점별 로그인 유도(FR-017).
- **Out of scope (지금 안 함):** 팀 보드 코멘트(FR-013), 음성 입력(FR-014), AI 맥락 보강(FR-015), 팀 구성·초대 흐름, 프로젝트 간 아이디어 연결(idea 확장), 데스크톱 전용 정리 화면 고도화.

  - **MVP (P0):** 즉시 캡처 + 게스트 시작 + 프로젝트 생성 + AI 매칭 추천·선택 + 프로젝트별 모아보기 — "던지고→AI로 분류하고→모아본다"는 핵심 가치 루프.

## 11. Assumptions
- 게스트로 던진 메모는 로컬/임시 보관되며, 로그인 시 사용자 계정에 연결(마이그레이션)된다.
- 로그인은 게스트 흐름을 막는 진입 장벽이 아니라 선택적 단계이며, 특정 시점(공유·기기 변경·메모 누적 등)에만 부드럽게 유도한다. "마찰 0" 캡처 가치를 해치지 않는 게 우선이다.
- AI 매칭은 메모 텍스트와 기존 프로젝트의 이름·소속 메모를 근거로 후보를 산출하며, 기본 추천 후보는 상위 3개 안팎이다.
- 팀 보드는 프로젝트 단위로 존재하고, 공유 대상 팀원은 이미 연결돼 있다고 가정한다(팀 생성·초대 흐름은 v1 범위 밖).
- 모든 메모는 기본적으로 개인 공간에 머물고, 명시적으로 "공유"한 것만 팀 보드로 올라간다.
- 플랫폼은 반응형 웹, 모바일 우선 뷰포트 기준.
