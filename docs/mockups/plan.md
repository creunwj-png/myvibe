# Mockup Plan — 톡캐치 (TokCatch)

> 작성일: 2026-06-12

## Overview

이 문서는 PRD와 userflow를 화면 단위로 쪼갠 프론트엔드 목업 스프린트 계획이다. 코드를 작성하지 않고, "던지고 → AI로 분류하고 → 모아본다 → 골라 공유한다"는 핵심 가치 루프를 사용자가 눈으로 리뷰할 수 있는 화면들로 정리한다. 각 화면은 독립적으로 리뷰·수정·확정할 수 있고, 이후 `mockup-build` 단계에서 한 화면씩 구현·체크한다.

시각 방향은 docs/DESIGN.md(카카오 기반 디자인 시스템 — 평평한 화이트 캔버스 + 단일 시그널 옐로 `#FEE500`)를, 문구 톤은 docs/brandvoice.md("화자로 나서지 않는 조용한 도구 · 간결·빠름·믿음직")를 따른다.

## Source Context

- **PRD:** v1 범위 FR-001~012, FR-016·017 반영. 핵심 시나리오 3개(첫 던지기 / 반복 던지기+AI 매칭 / 모아보고 공유). 8장 화면·정보 구조 표를 화면 후보의 1차 기준으로 사용.
- **User Flows:** 플로우 1(던지기 — 환영→캡처→AI매칭→홈)과 플로우 2(모아보고 키우기 — 홈→프로젝트 상세→메모 상세→공유). AI 매칭은 케이스 A(추천 모드)와 케이스 B(빈 프로젝트·즉석 등록)를 한 화면의 두 상태로 통합.
- **Additional Context:**
  - docs/DESIGN.md — 색·타이포·컴포넌트(캡처 입력 `#F0F0F0`/20px, 던지기 CTA `#FEE500`/12px, 카드 평면, 옐로는 던지기·매칭·완료 순간에만), 모바일 우선 반응형, 이모지 대신 lucide 아이콘.
  - docs/brandvoice.md — UI 카피 톤(던진 직후 "○○에 담았어요", 매칭은 "어디로 갈까요?", 재촉·생색·호들갑 금지, 존댓말 `~해요`).
  - docs/idea.md — 가치 루프와 "마찰 0 캡처" 우선순위.

## Mockup Scope

이번 스프린트에서 그릴 화면(상태 포함):

- S001 환영 화면 — 첫 진입·가치 전달
- S002 캡처 화면 — 자동 포커스 입력, 던지기
- S003 AI 매칭 & 분류 — 추천 모드(케이스 A) / 빈 프로젝트 즉석 등록(케이스 B) / 분류 없이 저장
- S004 홈 — 채워진 상태 / 빈 상태 / 던진 직후 확인 토스트 / 검색
- S005 프로젝트 상세 — 메모 카드 리스트(공유 배지 포함)
- S006 메모 상세·편집 — 인라인 편집 / 재분류 / 수정·삭제 / 공유 진입
- S007 공유 — 팀 보드로 올리기 / 완료 토스트 / [보드 보기]
- S008 로그인·가입 — 공유 시점 게스트 로그인 요구 / 시점별 로그인 유도(부드러운 권유) / [나중에] 게스트 유지
- S009 팀 보드 — 한 프로젝트의 공유 메모 모아보기 / 빈 상태 (코멘트 작성은 v1 확장, 자리만)

상태 우선순위: 모든 화면의 Default를 먼저 확정하고, 그다음 Empty·Selected·Toast·Error 순으로 채운다.

## Out of Scope

- 실제 인증 로직, 토큰/세션, 게스트→계정 데이터 마이그레이션 실제 동작 (화면 UI만 목업)
- 실제 AI 매칭 추론 — 추천 칩은 더미 데이터로 표현
- DB 저장, API 연동, 오프라인 동기화 실제 구현
- 팀 보드 코멘트 작성·스레드 (FR-013, v1 확장) — S009는 공유 메모를 모아 보는 뷰까지만, 코멘트는 자리만
- 음성 입력(FR-014), AI 맥락 보강(FR-015), 팀 생성·초대 흐름
- 데스크톱 전용 정리 화면 고도화 (반응형 노트 수준까지만)

## Screen Flow

```text
[S001 환영]
  -> [S002 캡처]
      -> [S003 AI 매칭 & 분류]
          -> [S004 홈]
              -> [S002 캡처]            (+ 아이디어 던지기 / 반복)
              -> [S005 프로젝트 상세]
                  -> [S002 캡처]        (이 프로젝트에 던지기)
                  -> [S009 팀 보드]     (팀 보드 보기 — 공유 메모 모아보기)
                  -> [S006 메모 상세·편집]
                      -> [S007 공유]
                          -> [S008 로그인·가입]   (게스트일 때만)
                          -> [S004 홈]            (완료 후 홈으로)
                          -> [S009 팀 보드]       (완료 후 보드 보기)
```

## [x] Screen S001 - 환영 화면

**Purpose:** 톡캐치의 가치("던질 땐 가볍게, 정리는 알아서")를 한눈에 전하고 마찰 없이 게스트로 진입시킨다.

**User Moment:** 플로우 1 ① — 처음 앱을 여는 순간.

**Primary Action:** [바로 시작하기] → S002

**Leads To:** S002 캡처 화면

**States to Mock:** Default (단일 정적 화면)

**Review Focus:**
- [ ] 가치 한 줄이 "가벼움 + 똑똑함" 두 박자를 동시에 전달하는가?
- [ ] "로그인 없이 시작"이 부담 없이 읽히는가 (장벽이 아니라 안심으로)?

**Done When:**
- [ ] 가치 한 줄·시각 한 컷·[바로 시작하기]가 한 화면에 담기고, 톤이 brandvoice와 맞는다.

## [x] Screen S002 - 캡처 화면

**Purpose:** "1초에 던진다"의 심장. 머릿속 키워드를 옮기는 단 하나의 행동에만 집중시킨다.

**User Moment:** 플로우 1 ② / 플로우 2의 반복 캡처.

**Primary Action:** 텍스트 입력 → [던지기] → S003

**Leads To:** S003 (던지기) / S004 (✕ 닫기)

**States to Mock:** Default(자동 포커스·빈 입력, 던지기 비활성) / 입력 있음(던지기 활성) / 프로젝트 컨텍스트 진입(상단에 "○○에 던지는 중")

**Review Focus:**
- [ ] 열자마자 입력 외에 시선을 끄는 요소가 없는가 (마찰 0)?
- [ ] 빈 입력일 때 [던지기]가 막혀 있다는 게 자연스럽게 보이는가?

**Done When:**
- [ ] 자동 포커스 입력창 + [던지기] + ✕만으로 화면이 구성되고, 빈/입력 상태가 구분된다.

## [x] Screen S003 - AI 매칭 & 분류

**Purpose:** 자동(오배치)도 수동(마찰)도 아닌 반자동 분류. 던진 내용을 위에 고정하고 같은 화면에서 추천을 펼친다.

**User Moment:** 플로우 1 ③ / 플로우 2의 반복 던지기.

**Primary Action:** 추천 칩 1탭(케이스 A) 또는 새 이름 입력 후 [만들고 담기](케이스 B) → S004

**Leads To:** S004 홈

**States to Mock:** 케이스 A(추천 칩 ‹유력› 표시·기존 프로젝트 있음) / 케이스 B(프로젝트 0개·즉석 등록) / 분류 없이 저장 / (선택) 추천 로딩

**Review Focus:**
- [ ] "어디로 갈까요?" 톤이 결정을 사용자에게 넘기는 느낌인가 (생색 금지)?
- [ ] ‹유력› 표시가 1개 후보에만 붙어 1초 선택을 유도하는가?
- [ ] 케이스 A/B 전환이 같은 화면의 상태 변화로 자연스러운가?

**Done When:**
- [ ] 던진 내용 고정 + 추천 칩/새 프로젝트 입력 + 분류 없이 저장이 한 화면의 상태들로 표현된다.

## [x] Screen S004 - 홈

**Purpose:** 던진 게 어디 들어갔는지 확인시키고(aha 마무리), 프로젝트별 점검과 반복 캡처의 허브가 된다.

**User Moment:** 플로우 1 ④ (결과 확인) / 플로우 2 ① (채워진 홈에서 출발).

**Leads To:** S005, S002

**States to Mock:** 채워진 상태(프로젝트 그룹·개수, 최근순) / 빈 상태(프로젝트 0개) / 던진 직후 확인 토스트("'○○'에 담았어요") / 검색 활성 / 미분류 묶음 노출

**Review Focus:**
- [ ] 확인 토스트가 짧고 따뜻한가 ("저장 완료" 톤 금지)?
- [ ] 프로젝트가 많아질 때 최근순 정렬·개수 표기가 스캔하기 좋은가?
- [ ] [+ 아이디어 던지기]가 항상 하단에 고정되어 즉시 캡처로 이어지는가?

**Done When:**
- [ ] 채워진/빈/토스트 상태가 표현되고, 하단 고정 캡처 버튼과 검색 진입이 있다.

## [x] Screen S005 - 프로젝트 상세

**Purpose:** 한 프로젝트의 아이디어를 한눈에 모아 회의 전 점검한다.

**Review Focus:**
- [ ] 메모 미리보기·시각·공유 배지가 카드에서 한눈에 구분되는가?

- [ ] 공유 메모가 있을 때 [팀 보드 보기] 진입이 눈에 들어오는가?

**Done When:**
- [ ] 메모 카드 리스트(공유 배지 포함)와 프로젝트 컨텍스트 캡처 진입이 표현된다.
- [ ] 공유 메모가 있으면 [팀 보드 보기](S009) 진입이 표현된다.

**Purpose:** 개인 공간의 메모를 고른 것만 팀 보드로 올려 함께 발전시킨다.

## [x] Screen S008 - 로그인·가입

**Purpose:** 공유·기기 변경·메모 누적 등 특정 시점에 계정 연결을 부드럽게 권유하되, 거절해도 게스트 흐름을 끊지 않는다.

**User Moment:** 플로우 2 ④의 공유 시점 로그인 요구 (FR-011, FR-016, FR-017).

**States to Mock:** 공유 시 로그인 요구(데이터 연결 안내·[나중에]) / 시점별 부드러운 권유(누적·기기변경) / 인증 오류(데이터 보존, 재시도)

**Review Focus:**
- [ ] 로그인이 "장벽"이 아니라 "데이터를 안전히 잇는 선택"으로 읽히는가?

**Done When:**

## [ ] Screen S009 - 팀 보드

**Purpose:** 한 프로젝트에서 "공유"한 메모만 모이는, 팀과 함께 보는 공간. 개인 공간과 분리된 "올라간 곳"을 실제로 가서 확인하게 한다. (프로젝트 1 : 팀 보드 1)

**User Moment:** 플로우 2 ④ 이후 — 올린 걸 확인하거나, 회의 전 "팀에 공유된 것"만 따로 점검.

**Primary Action:** 보드 카드 탭 → S006

**Leads To:** S006(메모 상세), S005(← 뒤로), S004(🏠 홈)

**States to Mock:** Default(공유 메모 카드 리스트·"내가 올림·시각"·코멘트 자리) / 빈 상태(공유 0개 안내)

**Review Focus:**
- [ ] "여기가 팀이 보는 곳"이라는 분리감이 느껴지는가?
- [ ] 개인 메모(주황 카드)와 시각적으로 구분되는가?
- [ ] 코멘트가 아직 없음을 과장 없이(자리만) 보여주는가?

**Done When:**
- [ ] 해당 프로젝트의 공유 메모만 모인 리스트와 빈 상태가 표현되고, 카드 탭(S006)·뒤로(S005) 흐름이 설명 가능하다.
