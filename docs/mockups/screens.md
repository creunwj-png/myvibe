# Mockup Screens — 톡캐치 (TokCatch)

> Vibe Build · mockup-plan 산출물
> 작성일: 2026-06-12
> 짝 문서: docs/mockups/plan.md (화면 목록·흐름)

## Overview

각 화면의 상세 설계다. plan.md의 화면 ID(S001~S008)와 1:1로 대응한다. 화면마다 목적·진입/이탈·핵심 행동·ASCII 도식·UI 영역·카피 노트·더미 데이터·상태·반응형·리뷰 질문·확정 기준을 담는다. ASCII 도식은 정교한 와이어프레임이 아니라 정보 구조를 빠르게 읽기 위한 것이다. 시각 토큰·컴포넌트는 docs/DESIGN.md, 문구 톤은 docs/brandvoice.md를 따른다.

## Global Mockup Assumptions

- **레이아웃:** 모바일 우선 단일 컬럼, 가로 패딩 16px(DESIGN.md). 최대 폭 약 480px 기준의 모바일 프레임으로 목업.
- **내비게이션:** 하단 고정 [+ 아이디어 던지기]가 캡처 진입의 기본. 별도 탭바는 두지 않는다(홈 중심 구조).
- **색·컴포넌트:** 화이트 캔버스 + 시그널 옐로 `#FEE500`은 던지기·매칭 ‹유력›·완료 확인에만. 카드 평면(그림자 최소), 12px 라운드 표준, 캡처 입력은 `#F0F0F0`/20px. 아이콘은 lucide-react(이모지 사용 안 함 — 도식의 🔍/✕/⚙ 등은 ASCII 표기용 기호일 뿐 실제 구현은 SVG 아이콘).
- **더미 데이터:** 프로젝트 예시 — 결제개편(5) · 온보딩리뉴얼(3) · 검색고도화(2) · 로그인개선(1). 메모 예시 — "로그인 화면 A/B 테스트 해보면 어떨까", "PG사 수수료 비교", "결제 실패 리트라이". 시각 표기 — 방금 / 어제 / 2일 전 / 3일 전.
- **톤:** 존댓말 `~해요`. 던진 직후 "'○○'에 담았어요". 매칭은 "어디로 갈까요?". 재촉·생색·호들갑·시스템 로그 톤 금지.
- **반응형:** Mobile(<480px) 풀 충실도. Tablet/Desktop은 중앙 정렬 + 여백 확장 수준(데스크톱 정리 화면 고도화는 범위 밖).

## Screen S001 - 환영 화면

**Purpose:** 톡캐치의 가치를 한눈에 전하고 마찰 없이 게스트로 진입시킨다.

**Entry Points:**
- 앱 최초 진입(게스트, 미로그인)

**Exit Points:**
- [바로 시작하기] → S002 캡처 화면

**Primary User Action:** [바로 시작하기]

**Secondary Actions:**
- "로그인 없이 시작" 안내 (별도 버튼 아님 — 안심 문구)

**Layout ASCII:**

```text
+----------------------------------+
|                                  |
|            [  💭 → 📁  ]         |   ← 던지기→정리 시각 한 컷
|                                  |
|        떠오르면 툭,              |   ← Display Hero 28~36 / 800
|        정리는 알아서.            |
|                                  |
|     키워드만 던지면 AI가         |   ← Body 16 / #666
|     프로젝트로 정리해드려요.     |
|                                  |
|                                  |
|   +--------------------------+   |
|   |      바로 시작하기       |   |   ← Primary CTA (#FEE500/12px)
|   +--------------------------+   |
|                                  |
|        로그인 없이 시작          |   ← Caption #999
|                                  |
+----------------------------------+
```

**Key UI Regions:**
- Hero Visual: 던지기→정리를 상징하는 한 컷(추상 도형/일러스트)
- Headline: 가치 한 줄(가벼움 + 똑똑함)
- Subcopy: 한 문장 보강 설명
- Actions: [바로 시작하기] 단일 CTA + 게스트 안심 문구

**Content / Copy Notes:**
- 헤드라인: "떠오르면 툭, 정리는 알아서." (brandvoice 온보딩 예시)
- 서브카피: "키워드만 던지면 AI가 프로젝트로 정리해드려요."
- CTA: "바로 시작하기" / 하단: "로그인 없이 시작"
- 금지: "혁신", 감탄사·느낌표 남발, AI 생색.

**Data / Placeholder Needs:**
- 히어로 비주얼(플레이스홀더 도형으로 대체 가능)

**States:**
- Default: 단일 정적 화면
- Empty: 해당 없음
- Loading: 해당 없음(스플래시는 범위 밖)
- Error: 해당 없음
- Selected / Active: 해당 없음

**Responsive Notes:**
- Mobile: 세로 중앙 정렬, CTA 풀폭(16px 마진)
- Desktop: 중앙 카드 형태로 좁게 유지, 여백만 확장

**Review Questions:**
- [ ] 가치 한 줄이 "가벼움 + 똑똑함"을 동시에 전달하는가?
- [ ] "로그인 없이 시작"이 장벽 제거(안심)로 읽히는가?
- [ ] 톤이 담담하고 따뜻한가(호들갑·과장 없음)?

**Acceptance Criteria:**
- [ ] 가치 한 줄·시각 한 컷·단일 CTA가 한 화면에 담긴다.
- [ ] [바로 시작하기]가 가장 명확한 단일 옐로 CTA다.
- [ ] S002로 이어지는 흐름이 설명 가능하다.

**Notes:**

게스트 우선 원칙(FR-002). 로그인은 여기서 권하지 않고 공유·동기화 시점(S008)으로 미룬다.

## Screen S002 - 캡처 화면

**Purpose:** 머릿속 키워드를 옮기는 단 하나의 행동([던지기])에만 집중시킨다.

**Entry Points:**
- S001 [바로 시작하기]
- S004 [+ 아이디어 던지기]
- S005 [+ 이 프로젝트에 던지기] (프로젝트 컨텍스트 진입)

**Exit Points:**
- [던지기] → S003 AI 매칭 & 분류
- ✕ 닫기 → S004 홈

**Primary User Action:** 텍스트 입력 후 [던지기]

**Secondary Actions:**
- ✕ 닫기
- 🎤 음성 입력(FR-014, 구현 완료) — 누르면 듣기 시작/멈춤, 말한 내용이 입력창에 실시간 반영

**Layout ASCII:**

```text
+----------------------------------+
|  ✕                               |   ← 닫으면 홈(S004)
|                                  |
|  ┃여기에 툭 던지세요             |   ← 자동 포커스, placeholder #BBB
|                                  |
|                                  |
|                                  |
+----------------------------------+
|  (🎤)               [ 던지기 ▸ ] |   ← Primary CTA, 빈 입력 땐 비활성
+----------------------------------+
|            (키보드)              |
+----------------------------------+
```

**Key UI Regions:**
- Top: ✕ 닫기만
- Main: 자동 포커스 입력창(캡처 입력 — `#F0F0F0`/20px 또는 평문 풀스크린)
- Action Bar: 하단 고정 [던지기] (입력 1자 이상일 때 활성)

**Content / Copy Notes:**
- placeholder: "여기에 툭 던지세요"
- CTA: "던지기"
- 프로젝트 컨텍스트 진입 시 상단에 작은 안내: "결제개편에 던지는 중" (Caption)
- 던지는 순간 프로젝트·태그·날짜를 일절 묻지 않는다.

**Data / Placeholder Needs:**
- 입력 텍스트(빈 / "로그인 화면 A/B 테스트 해보면 어떨까")
- 프로젝트 컨텍스트명(선택)

**States:**
- Default: 빈 입력 + 자동 포커스, [던지기] 비활성(opacity 0.5)
- Empty: Default와 동일(빈 입력 자체가 시작점)
- Loading: 해당 없음
- Error: 해당 없음(빈 입력은 전진 차단으로 처리)
- Selected / Active: 입력 1자 이상 → [던지기] 활성(#FEE500)

**Responsive Notes:**
- Mobile: 입력 영역이 화면 대부분, [던지기]는 키보드 위 고정
- Desktop: 중앙 컴포저 카드, Enter로 던지기 보조

**Review Questions:**
- [ ] 열자마자 입력 외에 시선을 끄는 요소가 없는가?
- [ ] 빈 입력일 때 [던지기]가 막혀 있음이 자연스럽게 보이는가?
- [ ] 프로젝트 컨텍스트 진입 표기가 방해되지 않는가?

**Acceptance Criteria:**
- [ ] 자동 포커스 입력 + [던지기] + ✕만으로 구성된다.
- [ ] 빈/입력 상태에 따라 [던지기] 활성/비활성이 구분된다.
- [ ] S003으로 이어지는 흐름이 설명 가능하다.

**Notes:**

FR-001(한 번의 행동으로 저장), Edge Case "빈 입력 전진 차단" 반영.

## Screen S003 - AI 매칭 & 분류

**Purpose:** 던진 내용을 위에 고정하고 같은 화면에서 추천을 펼쳐, 반자동(추천→1탭)으로 분류한다.

**Entry Points:**
- S002 [던지기]

**Exit Points:**
- 추천 칩 1탭 / [만들고 담기] / [분류 없이 저장] → S004 홈

**Primary User Action:** 추천 칩 1탭(케이스 A) 또는 새 프로젝트 이름 입력 후 [만들고 담기](케이스 B)

**Secondary Actions:**
- [+ 새 프로젝트] (케이스 A에서)
- [분류 없이 저장]
- ✕ 닫기

**Layout ASCII:**

케이스 A — 기존 프로젝트가 있을 때 (추천 모드)

```text
+----------------------------------+
|  ✕                               |
|  ┌────────────────────────────┐  |
|  │ "로그인 화면 A/B 테스트     │  |   ← 방금 던진 내용 (상단 고정)
|  │  해보면 어떨까"             │  |
|  └────────────────────────────┘  |
|                                  |
|  어디로 갈까요?                  |   ← Title, 결정은 사용자에게
|                                  |
|  [ ● 결제개편          ‹유력› ]  |   ← 1탭이면 끝 (유력=옐로 강조)
|  [ ○ 온보딩리뉴얼            ]  |
|  [ ○ 검색고도화              ]  |
|  ──────  또는  ──────            |
|  [ + 새 프로젝트 ]               |
|  [ 분류 없이 저장 ]              |   ← 보조 (System Pill 톤)
+----------------------------------+
```

케이스 B — 프로젝트가 하나도 없을 때 (첫 사용, 즉석 등록)

```text
+----------------------------------+
|  ✕                               |
|  ┌────────────────────────────┐  |
|  │ "로그인 화면 A/B 테스트     │  |   ← 방금 던진 내용 (고정)
|  │  해보면 어떨까"             │  |
|  └────────────────────────────┘  |
|                                  |
|  담을 프로젝트가 아직 없네요.    |
|  새로 만들까요?                  |
|                                  |
|  프로젝트 이름                   |
|  [____________________________]  |   ← 직접 입력(자동 포커스)
|                                  |
|  [      만들고 담기       ]      |   ← Primary CTA
|  [    분류 없이 저장      ]      |   ← 보조
+----------------------------------+
```

**Key UI Regions:**
- Pinned Memo: 방금 던진 내용(상단 고정, Accent/Plain Bubble)
- Prompt: "어디로 갈까요?" / "새로 만들까요?"
- Recommendation List: 추천 프로젝트 칩(케이스 A) — 첫 칩에 ‹유력›
- New Project Input: 이름 직접 입력(케이스 B, 또는 A의 [+ 새 프로젝트])
- Secondary: [분류 없이 저장]

**Content / Copy Notes:**
- 케이스 A 헤더: "어디로 갈까요?"
- 케이스 B 헤더: "담을 프로젝트가 아직 없네요. 새로 만들까요?"
- 보조: "분류 없이 저장"
- 금지: "AI가 분석했어요 / 제가 골랐어요"(생색). 톡캐치는 후보만 펼친다.

**Data / Placeholder Needs:**
- 던진 메모 텍스트
- 추천 프로젝트 3개(더미) + ‹유력› 1개
- 새 프로젝트 이름 입력값

**States:**
- Default(케이스 A): 추천 칩 표시, 첫 칩 ‹유력›
- Empty(케이스 B): 프로젝트 0개 → 즉석 등록 입력
- Loading: (선택) 추천 산출 중 — 칩 자리 스켈레톤(`#F0F0F0`)
- Error: 추천 실패 시 케이스 B 형태로 폴백(직접 입력)
- Selected / Active: 칩 선택 시 옐로 채움 → 즉시 S004 전이

**Responsive Notes:**
- Mobile: 칩 세로 스택, 한 손 탭 영역 확보
- Desktop: 칩 2열까지 허용 가능, 던진 내용은 상단 고정 유지

**Review Questions:**
- [ ] "어디로 갈까요?"가 결정을 사용자에게 넘기는 톤인가?
- [ ] ‹유력›이 1개 후보에만 붙어 1초 선택을 유도하는가?
- [ ] 케이스 A/B 전환이 같은 화면의 상태 변화로 자연스러운가?
- [ ] [분류 없이 저장]이 부담 없이 빠져나가는 보조로 보이는가?

**Acceptance Criteria:**
- [ ] 던진 내용 고정 + 추천/즉석 등록 + 분류 없이 저장이 한 화면 상태들로 표현된다.
- [ ] 옐로 강조가 ‹유력›과 Primary CTA에만 쓰인다.
- [ ] 어떤 분기로 끝내도 S004로 이어진다.

**Notes:**

FR-003·004·005. 추천 개수(3개 가정)·신뢰도 표시 방식은 plan.md Open Questions와 SC-004 오픈 이슈로 연결.

## Screen S004 - 홈

**Purpose:** 던진 게 어디 들어갔는지 확인시키고, 프로젝트별 점검과 반복 캡처의 허브가 된다.

**Entry Points:**
- S003 분류 완료
- S002 ✕ 닫기
- S005 ← 뒤로
- S007 공유 완료

**Exit Points:**
- 프로젝트 그룹 탭 → S005
- [+ 아이디어 던지기] → S002
- 🔍 검색 → 검색 상태

**Primary User Action:** 프로젝트 그룹 탭(점검) 또는 [+ 아이디어 던지기](반복 캡처)

**Secondary Actions:**
- 🔍 검색
- ⚙ 설정(자리)
- 미분류 묶음 열기

**Layout ASCII:**

채워진 상태 (+ 던진 직후 확인 토스트)

```text
+----------------------------------+
|  톡캐치               🔍    ⚙   |
+----------------------------------+
|  ✓ '로그인개선'에 담았어요       |   ← 확인 토스트(옐로 체크, 1초)
+----------------------------------+
|  📁 결제개편                  5  |
|  📁 온보딩리뉴얼              3  |
|  📁 검색고도화                2  |
|  📁 로그인개선                1  |
|  ─────────────────────────────  |
|  ⦿ 미분류                     2  |   ← 별도 묶음
+----------------------------------+
|   +--------------------------+   |
|   |    + 아이디어 던지기     |   |   ← 하단 고정 (#FEE500)
|   +--------------------------+   |
+----------------------------------+
```

빈 상태 (프로젝트 0개)

```text
+----------------------------------+
|  톡캐치                     ⚙   |
+----------------------------------+
|                                  |
|        아직 비어 있어요.         |   ← Empty: 다음 행동 1개
|     떠오르는 걸 툭 던져보세요.   |
|                                  |
+----------------------------------+
|   +--------------------------+   |
|   |    + 아이디어 던지기     |   |
|   +--------------------------+   |
+----------------------------------+
```

검색 상태

```text
+----------------------------------+
|  ←  [🔍 메모 검색            ]   |   ← Search input #F0F0F0/20px
+----------------------------------+
|  "로그인" 결과                   |
|  ┌────────────────────────────┐  |
|  │ 로그인 화면 A/B 테스트...   │  |
|  │ · 로그인개선 · 방금         │  |
|  └────────────────────────────┘  |
+----------------------------------+
```

**Key UI Regions:**
- Header: 워드마크 "톡캐치" + 🔍 + ⚙
- Toast(조건부): 던진 직후 확인
- Project Groups: 프로젝트별 그룹(이름·개수, 최근 활동순) + 미분류 묶음
- Bottom Fixed: [+ 아이디어 던지기]

**Content / Copy Notes:**
- 토스트: "'로그인개선'에 담았어요" (이름은 실제 값, ✓ 1개)
- 빈 상태: "아직 비어 있어요. 떠오르는 걸 툭 던져보세요."
- 미분류: "미분류" 라벨(중립)
- 금지: "저장 완료", 동기부여 코치 톤.

**Data / Placeholder Needs:**
